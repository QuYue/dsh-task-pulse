# 踩坑记录

## 2026-11-03 步骤顺序错乱

- **现象**：B1 微调步骤（s7–s11）在 B2（s3）之后/之前的位置不符合预期，
  `s1,s2,s3,s4` 不再连续。
- **原因**：`plan.steps` 原先只有数组顺序，没有排序字段；`revise` 把新步骤
  **追加到数组末尾**，展示层也按数组顺序渲染。所以“后补的步骤”只能排在最后，
  无法插到已有步骤之间。
- **修复**：
  - 步骤新增可选 `order`（数值越小越靠前）；
  - `build_run_view` 按 `(阶段顺序, order, 数组位置)` 排序；
  - `revise` 新增步骤时由 Lead 指定 `order`，即可插到目标位置；
  - 文档（`SKILL.md` / `contract.md`）补充用法。
- **约定**：Lead 重写计划时必须检查完整顺序，不要依赖 append 顺序；
  `order` 相同则按数组位置。步骤 id 不随顺序变化，不要为了排序重命名 id。

## 2026-11-03 `/live-progress` 没有自动记账

- **现象**：用户发了 `/live-progress` 并让开始 B2，但看板还停在 B1。
- **原因**：`/live-progress` 只是把 skill 指令加载给模型，**不会自动创建任务、不会写事件、
  也不会弹卡片**。真正记账必须显式执行 `board.py status/start/report/done`。
  当时继续已有任务，却漏了 `start s3`，所以看板没有“B2 已开始”。
- **修复/规则**：
  1. 继续已有任务：先 `board.py status` 找到当前步骤；
  2. 开始任何工作前先 `board.py start <step> --agent ...`；
  3. 每个工具边界至少心跳或 report，步骤结束必须 done/fail；
  4. 最终答复前自查：是否还有步骤停在进行中却没有解释。
- **提醒**：DSH 内卡片是 v2 功能，未安装前只有 8770 网页看板可见。
